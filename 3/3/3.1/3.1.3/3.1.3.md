# 3.1.3. Módulo 3: Caja y Facturación

**Integrante responsable:** RAMIREZ
**Formato de especificación:** Casos de uso

## Objetivo del módulo

Generar el cargo automático al cierre de una atención, registrar el cobro y el comprobante electrónico ante SUNAT, gestionar el cierre de caja diario y calcular la liquidación de honorarios por profesional, según el alcance definido en [1.1](../1.1/1.1.md) y las reglas de la sección "Cobro y facturación electrónica" de [1.3](../1.3/1.3.md).

## Actores del módulo

Caja, Administrador del establecimiento, Sistema (proceso automático de cargo y comprobante), SUNAT (sistema externo). Ver definiciones en [1.2](../1.2/1.2.md) y [2.3](../2.3/2.3.md).

## Especificación de casos de uso

### CU-01: Generar cargo automático al cierre de una atención

- **Actor(es):** Sistema (proceso automático)
- **Objetivo:** Generar el cargo correspondiente al servicio prestado en una atención recién cerrada, según el tarifario vigente del establecimiento.
- **Precondiciones:** Atención en estado "Cerrada" (firmada electrónicamente por el profesional en el Módulo 2).
- **Disparador:** El Módulo 2 cambia el estado de una atención a "Cerrada".
- **Flujo principal:**
  1. El sistema identifica el servicio prestado en la atención cerrada.
  2. El sistema consulta el tarifario vigente del establecimiento (Módulo 4) para ese servicio.
  3. El sistema genera el cargo asociado a la atención, con el monto correspondiente.
  4. El sistema deja el cargo disponible para Caja.
- **Flujos alternativos:**
  - 2a. El servicio no tiene tarifa configurada: el sistema genera el cargo en estado "Pendiente de configuración" y notifica al Administrador del establecimiento.
- **Postcondiciones:** Cargo generado y asociado a la atención cerrada.
- **Excepciones:** Toda atención cerrada debe generar un cargo (Cobro #1 de 1.3); no puede quedar cerrada sin pasar, en algún momento, a "Cobrada" o "Pendiente de pago".

---

### CU-02: Registrar cobro de una atención

- **Actor(es):** Caja / Administrador del establecimiento
- **Objetivo:** Registrar el pago efectuado por el paciente sobre un cargo generado.
- **Precondiciones:** Existe un cargo pendiente de cobro asociado a una atención cerrada; el paciente paga en el momento.
- **Disparador:** El paciente se acerca a caja para pagar tras su atención.
- **Flujo principal:**
  1. Caja ubica el cargo pendiente asociado al paciente/atención.
  2. Caja selecciona el medio de pago y registra el monto recibido.
  3. El sistema valida que el monto registrado corresponda al cargo generado.
  4. El sistema registra el cobro.
  5. El sistema dispara la emisión del comprobante electrónico (CU-03).
- **Flujos alternativos:**
  - 3a. Monto parcial o distinto al cargo: el sistema no permite cerrar el cobro hasta que coincida, o hasta aplicar un ajuste autorizado por el Administrador.
- **Postcondiciones:** Cobro registrado, asociado al cargo y a la atención.
- **Excepciones:** Solo los roles de Caja o Administrador del establecimiento pueden ejecutar este caso de uso (Registro por rol #3 de 1.3).

---

### CU-03: Emitir comprobante electrónico

- **Actor(es):** Caja / Administrador del establecimiento; Sistema (interacción con SUNAT)
- **Objetivo:** Emitir el comprobante de pago electrónico correspondiente a un cobro registrado y validarlo ante SUNAT.
- **Precondiciones:** Cobro registrado (CU-02) y aún no facturado.
- **Disparador:** Se completa el registro del cobro.
- **Flujo principal:**
  1. El sistema arma el comprobante con los datos del cobro y del establecimiento.
  2. El sistema envía el comprobante a SUNAT para su validación.
  3. SUNAT valida y registra el comprobante.
  4. El sistema recibe la confirmación y almacena el comprobante validado.
  5. El sistema cambia el estado de la atención a "Cobrada".
- **Flujos alternativos:**
  - 3a. SUNAT rechaza o no responde: el sistema reintenta según la política configurada y mantiene el cobro registrado sin comprobante validado hasta lograrlo, antes del cierre de caja del día.
- **Postcondiciones:** Comprobante electrónico válido emitido; atención en estado "Cobrada".
- **Excepciones:** Todo cobro efectivo debe generar un comprobante electrónico válido antes del cierre de caja del día (Cobro #3 de 1.3).

---

### CU-04: Marcar atención como "Pendiente de pago"

- **Actor(es):** Sistema
- **Objetivo:** Dejar explícitamente marcada como pendiente de pago una atención cerrada cuyo cargo no fue cobrado en el momento.
- **Precondiciones:** Atención en estado "Cerrada" con cargo generado; el paciente no paga de inmediato.
- **Disparador:** Caja indica que el paciente no cancela el cargo en el momento, o se cierra la atención sin registro de cobro asociado.
- **Flujo principal:**
  1. El sistema verifica que el cargo generado no tiene un cobro asociado.
  2. El sistema cambia el estado de la atención a "Pendiente de pago".
  3. El sistema deja el cargo visible en el listado de cargos pendientes (CU-06).
- **Flujos alternativos:** —
- **Postcondiciones:** Atención en estado "Pendiente de pago"; el sistema no la cierra de forma silenciosa (Cobro #2 de 1.3).
- **Excepciones:** —

---

### CU-05: Cobrar una atención pendiente de pago

- **Actor(es):** Caja / Administrador del establecimiento
- **Objetivo:** Registrar el cobro de una atención que había quedado marcada como pendiente de pago en una visita anterior.
- **Precondiciones:** Atención en estado "Pendiente de pago".
- **Disparador:** El paciente regresa a cancelar el cargo pendiente, o Caja lo contacta para regularizarlo.
- **Flujo principal:**
  1. Caja busca la atención pendiente de pago por paciente o por fecha.
  2. Caja registra el cobro (reutiliza CU-02).
  3. El sistema emite el comprobante electrónico correspondiente (CU-03).
  4. El sistema actualiza el estado de la atención a "Cobrada".
- **Flujos alternativos:** —
- **Postcondiciones:** Atención en estado "Cobrada".
- **Excepciones:** El tarifario aplicado es el vigente al momento en que se generó el cargo originalmente y no puede modificarse retroactivamente (Cobro #5 de 1.3).

---

### CU-06: Consultar cargos pendientes de cobro

- **Actor(es):** Caja / Administrador del establecimiento
- **Objetivo:** Visualizar los cargos generados que aún no han sido cobrados, para gestionar la cobranza.
- **Precondiciones:** Usuario autenticado con rol autorizado dentro del tenant.
- **Disparador:** El actor accede al listado de pendientes de pago.
- **Flujo principal:**
  1. El actor abre el listado de atenciones en estado "Pendiente de pago".
  2. El sistema muestra paciente, fecha de atención, servicio y monto pendiente.
- **Flujos alternativos:**
  - 2a. No hay pendientes: el sistema muestra un estado vacío.
- **Postcondiciones:** —
- **Excepciones:** —

---

### CU-07: Realizar cierre de caja diario

- **Actor(es):** Caja / Administrador del establecimiento
- **Objetivo:** Conciliar el total cobrado registrado en el sistema contra el ingreso declarado por el responsable de caja al final del día.
- **Precondiciones:** Es el fin de la jornada operativa del establecimiento.
- **Disparador:** El responsable de caja inicia el proceso de cierre diario.
- **Flujo principal:**
  1. El sistema calcula el total cobrado del día según los registros de cobro y comprobantes emitidos.
  2. Caja declara el ingreso efectivamente contado.
  3. El sistema compara ambos montos.
  4. Si coinciden, el sistema marca el cierre de caja del día como conciliado.
- **Flujos alternativos:**
  - 3a. Existe diferencia entre lo registrado y lo declarado: el sistema no autocorrige el monto y dispara CU-08 para registrarla.
- **Postcondiciones:** Cierre de caja del día registrado, conciliado o con diferencia documentada.
- **Excepciones:** No puede haber cobros efectivos sin comprobante electrónico válido antes del cierre (Cobro #3 de 1.3).

---

### CU-08: Registrar diferencia de cierre de caja

- **Actor(es):** Caja / Administrador del establecimiento
- **Objetivo:** Dejar constancia de una diferencia detectada entre el monto cobrado registrado en el sistema y el ingreso declarado en el cierre diario.
- **Precondiciones:** Se detectó una diferencia durante CU-07.
- **Disparador:** El sistema identifica que los montos no coinciden.
- **Flujo principal:**
  1. El sistema muestra el monto de la diferencia.
  2. Caja registra una observación o justificación de la diferencia.
  3. El sistema guarda la diferencia asociada al cierre de caja del día, sin alterar los montos originales.
- **Flujos alternativos:** —
- **Postcondiciones:** Diferencia de caja registrada y trazable para revisión del Administrador del establecimiento (Cobro #4 de 1.3).
- **Excepciones:** —

---

### CU-09: Calcular liquidación de honorarios por profesional

- **Actor(es):** Administrador del establecimiento
- **Objetivo:** Calcular el monto que corresponde pagar a cada profesional de salud por las atenciones cerradas y efectivamente cobradas dentro de un periodo.
- **Precondiciones:** Existen atenciones en estado "Cobrada" dentro del periodo de liquidación seleccionado.
- **Disparador:** El Administrador inicia el cálculo de liquidación del periodo.
- **Flujo principal:**
  1. El Administrador selecciona el profesional y el periodo de liquidación.
  2. El sistema filtra únicamente las atenciones de ese profesional que estén cerradas y cobradas dentro del periodo.
  3. El sistema aplica la regla de cálculo de honorarios configurada.
  4. El sistema muestra el detalle de atenciones consideradas y el monto total a liquidar.
- **Flujos alternativos:**
  - 2a. No hay atenciones cobradas en el periodo: el sistema muestra el resultado en cero, sin error.
- **Postcondiciones:** Liquidación de honorarios calculada, disponible para exportar o registrar el pago fuera del sistema.
- **Excepciones:** Las atenciones "Pendiente de pago" o "Derivadas" no se incluyen en el cálculo (Cobro #6 de 1.3).

---

### CU-10: Consultar historial de cobros de una atención o paciente

- **Actor(es):** Caja / Administrador del establecimiento
- **Objetivo:** Revisar el detalle de cargos, cobros y comprobantes asociados a una atención o a un paciente.
- **Precondiciones:** Usuario autenticado con rol autorizado dentro del tenant.
- **Disparador:** El actor necesita verificar el estado de pago de una atención.
- **Flujo principal:**
  1. El actor busca la atención o el paciente.
  2. El sistema muestra el cargo generado, el cobro (si existe) y el comprobante electrónico asociado.
